# 1️⃣ O que é qualidade?

A **qualidade** está relacionada ao grau em que um produto, serviço ou resultado atende aos requisitos definidos.

Em um projeto, qualidade significa produzir uma entrega que esteja de acordo com os critérios estabelecidos e que seja adequada ao objetivo pretendido.

### 🎯 Qualidade não significa apenas ausência de erros

Um produto pode funcionar tecnicamente e ainda não atender às necessidades dos usuários.

### 💡 Exemplo

Uma equipe desenvolve um aplicativo de vendas.

| Situação | Qualidade |
|---|---|
| 💻 Aplicativo funciona | Requisito técnico atendido |
| 🚀 Aplicativo responde rapidamente | Desempenho atendido |
| 📱 Interface é adequada | Usabilidade atendida |
| 🔐 Dados estão protegidos | Segurança atendida |
| 👥 Usuários conseguem realizar compras | Necessidade atendida |

> **Qualidade significa atender aos requisitos e às necessidades definidas para o projeto.**

# 2️⃣ Qualidade em projetos

A qualidade deve ser considerada durante todo o projeto, e não somente no momento da entrega.

Ela está relacionada a diferentes elementos:

- 📋 Requisitos;
- 📦 Escopo;
- ⭐ Critérios de aceitação;
- 📊 Processos;
- 🧪 Testes;
- 👥 Pessoas;
- 🛠️ Ferramentas;
- 📈 Indicadores;
- 📚 Padrões.

### 💡 Exemplo

Em um projeto de desenvolvimento de software:

**Requisito**

↓

**Desenvolvimento**

↓

**Teste**

↓

**Correção**

↓

**Validação**

↓

**Entrega**

A qualidade deve estar presente em todas essas etapas.

---

# 3️⃣ Requisitos e critérios de qualidade

Os requisitos estabelecem aquilo que o produto ou serviço precisa atender.

Os critérios de qualidade permitem verificar se esses requisitos foram cumpridos.

### 📊 Exemplo

| Requisito | Critério de qualidade |
|---|---|
| 🔐 Login seguro | Autenticação funcionando corretamente |
| ⚡ Sistema rápido | Resposta em até 2 segundos |
| 📱 Responsividade | Interface funcionando em diferentes dispositivos |
| 🛒 Compra | Pedido concluído corretamente |
| 📧 Notificação | E-mail enviado após a compra |

Os critérios precisam ser claros para permitir a avaliação das entregas.

# 4️⃣ Planejamento da qualidade

O **planejamento da qualidade** consiste em definir como a qualidade será alcançada e verificada durante o projeto.

### 📋 Elementos importantes

- 📋 Requisitos;
- ⭐ Padrões;
- 📊 Métricas;
- 🧪 Testes;
- 📦 Critérios de aceitação;
- 🛠️ Ferramentas;
- 👥 Responsabilidades;
- 📈 Indicadores.

### 💡 Exemplo

Um projeto define:

| Elemento | Definição |
|---|---|
| ⭐ Qualidade | Sistema sem erros críticos |
| ⚡ Desempenho | Resposta inferior a 2 segundos |
| 🔐 Segurança | Autenticação obrigatória |
| 🧪 Testes | Testes funcionais e de integração |
| 📊 Indicador | Percentual de erros encontrados |

O planejamento cria uma referência para acompanhar a qualidade.

---

# 5️⃣ Padrões de qualidade

Os **padrões de qualidade** estabelecem referências que devem ser utilizadas para avaliar processos e entregas.

Podem estar relacionados a:

- 📋 Requisitos internos;
- 🏢 Políticas organizacionais;
- 📚 Boas práticas;
- ⚖️ Regulamentações;
- 🌎 Normas;
- 🧪 Critérios técnicos.

### 💡 Exemplo

Uma empresa de software pode definir como padrão:

> Toda funcionalidade deve possuir testes antes de ser disponibilizada em produção.

Esse padrão orienta o trabalho da equipe.

# 6️⃣ Gerenciamento da qualidade

O gerenciamento da qualidade busca garantir que os processos utilizados no projeto sejam adequados para produzir os resultados esperados.

O foco está principalmente nos **processos** utilizados para alcançar a qualidade.

### 🔄 Exemplos de atividades

- 📋 Definir processos;
- 📊 Avaliar processos;
- 🔎 Identificar problemas;
- 🛠️ Propor melhorias;
- 📈 Acompanhar indicadores;
- 🔄 Implementar melhorias;
- 📚 Registrar aprendizados.

### 💡 Exemplo

Uma equipe percebe que muitos erros são encontrados somente após a entrega.

Ela pode analisar o processo de desenvolvimento e implementar:

- Revisão de código;
- Testes automatizados;
- Testes de integração;
- Checklist antes da entrega.

O objetivo é melhorar o processo para reduzir a ocorrência de problemas.

---

# 7️⃣ Controle da qualidade

O **controle da qualidade** consiste em verificar as entregas e identificar se os requisitos e critérios definidos foram atendidos.

### 🔎 Exemplos de atividades

- 🧪 Testar;
- 🔍 Inspecionar;
- 📊 Medir;
- 📋 Comparar;
- 🐛 Identificar defeitos;
- 🔧 Corrigir problemas;
- ✅ Validar resultados.

### 💡 Exemplo

Uma equipe desenvolveu uma tela de cadastro.

O controle da qualidade pode verificar:

| Critério | Resultado |
|---|---|
| Nome obrigatório | ✅ |
| E-mail validado | ✅ |
| Senha protegida | ✅ |
| Botão funcionando | ✅ |
| Mensagem de erro | ❌ |

Nesse caso, existe um problema que precisa ser tratado antes da entrega.

# 8️⃣ Gerenciamento × controle da qualidade

Os dois conceitos estão relacionados, mas possuem focos diferentes.

| Gerenciamento da qualidade | Controle da qualidade |
|---|---|
| 🔄 Foco nos processos | 📦 Foco nas entregas |
| 📋 Avalia como o trabalho é realizado | 🔎 Verifica o resultado |
| 🛠️ Busca melhorar processos | 🧪 Busca identificar problemas |
| 📈 Atua na prevenção e melhoria | 🔍 Atua na verificação |
| 🔄 Pode gerar melhorias no processo | 🔧 Pode gerar correções |

### 🧠 Exemplo

**Gerenciamento da qualidade:**

> Como podemos melhorar nosso processo de desenvolvimento?

**Controle da qualidade:**

> O sistema desenvolvido atende aos critérios definidos?

# 9️⃣ Prevenção × correção

Uma das ideias importantes da qualidade é evitar que problemas aconteçam.

### 🛡️ Prevenção

Busca evitar que um problema aconteça.

Exemplos:

- Code review;
- Testes automatizados;
- Treinamento;
- Padronização;
- Checklists.

### 🔧 Correção

Busca resolver um problema que já foi identificado.

Exemplos:

- Corrigir um bug;
- Refazer uma atividade;
- Ajustar um processo;
- Substituir um componente.

### 📊 Comparação

| Abordagem | Momento | Objetivo |
|---|---|---|
| 🛡️ Prevenção | Antes do problema | Evitar ocorrência |
| 🔎 Detecção | Durante a verificação | Identificar problema |
| 🔧 Correção | Após identificação | Resolver problema |

> **Prevenir problemas geralmente é mais eficiente do que descobrir problemas somente após a entrega.**

# 🔟 Métricas da qualidade

As **métricas da qualidade** permitem medir características relacionadas ao desempenho dos processos ou produtos.

### 📊 Exemplos

| Métrica | O que pode indicar |
|---|---|
| 🐛 Número de defeitos | Quantidade de problemas |
| 🧪 Cobertura de testes | Parte do código testada |
| ⏱️ Tempo de resposta | Desempenho |
| 🔄 Retrabalho | Eficiência do processo |
| 📈 Taxa de aprovação | Conformidade das entregas |
| 📉 Taxa de falhas | Frequência de problemas |
| ⭐ Satisfação | Percepção dos usuários |

### 💡 Exemplo

Uma equipe possui 100 funcionalidades testadas.

95 foram aprovadas na primeira avaliação.

**Taxa de aprovação = 95%**

Esse indicador pode ser acompanhado ao longo do projeto.

# 1️⃣1️⃣ Custos da qualidade

A qualidade também possui custos.

Esses custos podem estar relacionados à prevenção, avaliação e correção de problemas.

### 💰 Principais categorias

| Categoria | Exemplo |
|---|---|
| 🛡️ Prevenção | Treinamento e padronização |
| 🔎 Avaliação | Testes e inspeções |
| 🔧 Falhas internas | Retrabalho e correções antes da entrega |
| ⚠️ Falhas externas | Problemas encontrados pelo cliente |

### 💡 Exemplo

Uma empresa pode investir:

**R$ 5.000 em testes**

para evitar um problema que poderia gerar:

**R$ 30.000 em retrabalho e suporte.**

O investimento em prevenção pode reduzir custos relacionados às falhas.

---

# 1️⃣2️⃣ Retrabalho

O **retrabalho** ocorre quando uma atividade precisa ser realizada novamente para corrigir um problema ou atender aos requisitos.

### 💡 Exemplo

Um desenvolvedor implementa uma funcionalidade incorretamente.

O erro é identificado durante os testes.

Será necessário:

1. Identificar o problema;
2. Corrigir o código;
3. Executar novamente os testes;
4. Validar a correção;
5. Atualizar a entrega.

Esse trabalho adicional representa esforço que poderia ter sido evitado.

### 📊 Impactos do retrabalho

- 💰 Aumento de custos;
- 📅 Aumento do prazo;
- 👥 Maior utilização da equipe;
- ⚠️ Novos riscos;
- 📉 Redução da produtividade.

# 1️⃣4️⃣ Diagrama de Ishikawa

O **Diagrama de Ishikawa** é utilizado para analisar possíveis causas de um problema.

Ele também é conhecido como:

**Diagrama de causa e efeito.**

### 💡 Exemplo

Problema:

> 🐛 Sistema apresenta muitos erros.

Possíveis causas:

| Categoria | Possível causa |
|---|---|
| 👥 Pessoas | Falta de treinamento |
| ⚙️ Processo | Ausência de revisão |
| 💻 Tecnologia | Ferramentas inadequadas |
| 📋 Método | Processo não padronizado |
| 🧪 Testes | Poucos testes |

A ferramenta ajuda a organizar as possíveis causas de um problema.

---

# 1️⃣5️⃣ Técnica dos 5 Porquês

A técnica dos **5 Porquês** busca aprofundar a análise de um problema perguntando repetidamente **“por quê?”**.

### 💡 Exemplo

**Problema:** O sistema apresentou erro em produção.

**Por quê?**

→ Uma funcionalidade foi implementada incorretamente.

**Por quê?**

→ O código não foi revisado.

**Por quê?**

→ Não existia revisão obrigatória.

**Por quê?**

→ O processo não estava definido.

**Por quê?**

→ A equipe não havia estabelecido um padrão de revisão.

A análise pode revelar que o problema não está apenas no código, mas também no processo.

# 1️⃣6️⃣ Diagrama de Pareto

O **Diagrama de Pareto** ajuda a identificar quais problemas representam maior impacto.

### 💡 Exemplo

Uma equipe identificou:

| Problema | Ocorrências |
|---|---:|
| 🐛 Erros de validação | 40 |
| 📱 Problemas de interface | 25 |
| 🔐 Erros de autenticação | 20 |
| 📧 Problemas de e-mail | 10 |
| 📊 Outros | 5 |

A equipe pode utilizar essa informação para identificar quais problemas devem receber maior atenção.

> **O objetivo é direcionar esforços para os problemas mais relevantes.**

# 1️⃣7️⃣ Qualidade e melhoria contínua

A qualidade não deve ser tratada como uma atividade realizada apenas no final do projeto.

Ela pode fazer parte de um processo contínuo de melhoria.

### 🔄 Ciclo de melhoria

**Planejar**

↓

**Executar**

↓

**Verificar**

↓

**Melhorar**

↓

**Planejar novamente**

Esse processo permite utilizar os resultados obtidos para melhorar as próximas atividades.

### 💡 Exemplo

Após uma entrega, a equipe identifica muitos erros.

Em vez de apenas corrigir os problemas, pode analisar:

- Por que os erros ocorreram?
- Em qual etapa foram introduzidos?
- Como poderiam ter sido identificados antes?
- Que mudança no processo poderia evitar novos erros?

# 2️⃣0️⃣ Qualidade e outras áreas do projeto

A qualidade está relacionada às demais áreas do gerenciamento.

### 🧩 Exemplo

Uma alteração no escopo pode gerar:

**Novo requisito**

↓

**Mais desenvolvimento**

↓

**Mais testes**

↓

**Mais recursos**

↓

**Maior prazo**

↓

**Possível aumento de custos**

A qualidade precisa ser considerada durante essas decisões.

### 📊 Relação entre áreas

| Área | Relação com qualidade |
|---|---|
| 📦 Escopo | Define o que precisa ser entregue |
| 📅 Cronograma | Define quando será entregue |
| 💰 Custos | Define recursos disponíveis |
| 👥 Recursos | Define quem realizará o trabalho |
| ⚠️ Riscos | Identifica possíveis problemas |
| 💬 Comunicação | Compartilha critérios e resultados |
| 👥 Stakeholders | Define expectativas e necessidades |

# 2️⃣1️⃣ Exemplo completo

Uma empresa está desenvolvendo um aplicativo de vendas.

Foram definidos os seguintes critérios:

| Critério | Meta |
|---|---|
| ⚡ Tempo de resposta | Até 2 segundos |
| 🐛 Erros críticos | 0 |
| 📱 Responsividade | 100% das telas |
| 🔐 Segurança | Autenticação obrigatória |
| 🧪 Cobertura de testes | Mínimo de 80% |
| ⭐ Aprovação do cliente | 100% dos requisitos |

Durante os testes foram encontrados:

- 3 erros críticos;
- 5 problemas de interface;
- Tempo médio de resposta de 3 segundos;
- Cobertura de testes de 72%.

### 🔎 Análise

Os resultados estão abaixo dos critérios definidos.

A equipe deverá:

1. Identificar as causas;
2. Corrigir os problemas;
3. Executar novamente os testes;
4. Verificar os indicadores;
5. Validar as entregas;
6. Registrar os resultados.
